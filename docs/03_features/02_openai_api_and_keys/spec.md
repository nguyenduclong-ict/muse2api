# Feature Spec: OpenAI-Compatible API (`/v1/*`) & API Key

- **Trạng thái:** `Ready for Implementation`
- **Liên quan:** [API Overview](../../02_basic_design/01_api_overview.md), [System Architecture](../../02_basic_design/00_system_architecture.md)

## 1. Mục tiêu & Bối cảnh
Cung cấp đầu API chuẩn OpenAI (`/v1/*`) đầy đủ tính năng tương đương `../muse2api` cho các ứng dụng bên thứ 3 gọi trực tiếp qua WSS Noise tunnel, đồng thời cho phép xem/copy/xoay 1 API Key duy nhất lưu dạng raw trong SQLite.

## 2. Phạm vi
- **In Scope:**
  - Endpoints: `/v1/models` (đầy đủ alias gồm cả TTS), `/v1/chat/completions` (SSE + non-stream, multimodal `image_url`, top-level `prompt`, `MUSE2API_TOOL_PROTOCOL`), `/v1/responses` (SSE + non-stream, `instructions`), `/v1/images/generations`, `/v1/images/edits` (multipart & JSON), `/v1/images/tasks` (+ `/{id}` & `Idempotency-Key`), `/v1/videos` & `/v1/videos/generations` (+ `/{id}`), `/v1/audio/voices`, `/v1/audio/speech`, `/v1/media/{name}`.
  - Quản lý 1 Client API Key (`m2a_...`) lưu raw trong bảng `api_keys`.
- **Out of Scope:**
  - Endpoint bất đồng bộ riêng cho TTS (`/v1/audio/tasks`) và chuyển đổi định dạng audio ngoài `.mp3`/`.wav` (`opus`, `aac`, `flac`, `pcm`).
  - Quản lý nhiều API Key phân quyền theo từng user/app.

## 3. Yêu cầu chức năng (`FR`)
- **FR-101 (Xác thực `/v1/*`):** Mọi request tới `/v1/*` (trừ `/v1/media/{name}`) phải kiểm tra `Authorization: Bearer <key>` khớp `api_keys.raw_key`.
- **FR-102 (Quản lý 1 API Key Raw):** Khởi tạo tự động 1 key `m2a_<random>` nếu bảng `api_keys` trống (hoặc lấy từ `MUSE2API_KEY` trong `.env`). API `GET /admin/apikey` trả về `raw_key` nguyên văn để Admin xem/copy; `POST /admin/apikey/rotate` tạo key mới thay thế ngay lập tức.
- **FR-103 (Chat Completions qua WSS):** Gửi `POST /chat/stream` và subscribe `POST /chat/subscribe` để nhận delta text theo thời gian thực, chuyển đổi thành SSE `chat.completion.chunk` (hoặc JSON sync). Hỗ trợ `messages` kèm `image_url`, top-level `prompt` khi `messages` rỗng, và tùy chọn `MUSE2API_TOOL_PROTOCOL` (`0` mặc định) cho `tools`/`tool_calls`.
- **FR-104 (Image & Video Generation qua WSS):** Gửi prompt sinh ảnh/video qua `POST /chat/stream`, theo dõi `POST /chat/subscribe` đến khi `task.status == "completed"`, đọc `GET /chat/history` lấy path resource, tải binary qua `GET /media/raw/<path>` về `data/media/` và trả URL `/v1/media/<filename>` hoặc `b64_json`.
- **FR-105 (LRU Pool, Lọc Model hỗ trợ & Failover):** Chọn tài khoản `enabled=true`, chưa hết quota, bật loại model tương ứng với endpoint (`chat`, `image`, `video`, `speech`, xem `BR-111`), ưu tiên `status="healthy"` và `last_used_at` cũ nhất; nếu tài khoản lỗi `401` hoặc timeout khi bắt đầu stream, tự động retry sang tài khoản hợp lệ khác trong pool. Nếu không có tài khoản ứng viên nào, trả `503 Service Unavailable` ngay lập tức.
- **FR-106 (`/v1/responses` Streaming & `instructions`):** Hỗ trợ `stream=true` trả SSE events (`response.created`, `response.output_text.delta`, `response.completed`) và đọc trường `instructions` để ghép vào prompt gửi qua WSS.
- **FR-107 (`GET /v1/models` Alias đầy đủ):** Trả đầy đủ danh sách model alias tương đương v1 (`muse-spark`, `gpt-4o`, `gpt-4o-mini`, `gpt-5`, `claude-sonnet-4`, `claude-opus-4`, `deepseek-chat`, `gemini-2.5-pro`, `muse-image`, `muse-video`, `muse-tts`, `tts-1`, `tts-1-hd`, `gpt-4o-mini-tts`, v.v.).
- **FR-108 (Reference Media & SSRF Guard):** Hỗ trợ đầu vào media tham chiếu (`image`, `images`, `image_url`, `reference_image`, `videos`, `audios`, `files` từ URL công khai hoặc base64/data URL; multipart `image`, `image[]`, `video`, `audio`, `file`) trên `/v1/images/generations`, `/v1/images/edits`, `/v1/images/tasks`, `/v1/videos*` và `image_url` trong `/v1/chat/completions`.
- **FR-109 (Async Flag, Idempotency & Task Metadata):** Hỗ trợ `async=true` trên `/v1/images/generations` và `/v1/images/edits`, header `Idempotency-Key` trên `/v1/images/tasks`, các tham số `aspect_ratio`, `resolution`, `extra`, `timeout`, và trả đầy đủ metadata (`progress`, `size`, `kind`, `bytes`, `b64_json`) ở `GET /v1/images/tasks/{id}` và `GET /v1/videos/{id}`.
- **FR-110 (Collapsible Endpoint Docs & Stable Controls):** Danh sách Available `/v1/*` Endpoints trên UI hỗ trợ đóng/mở (collapse) xem schema Input & Output (gồm cả `GET /v1/audio/voices` và `POST /v1/audio/speech`); các nút `Show/Hide` và `Copy/Copied` giữ cố định chiều rộng để không làm lệch layout.
- **FR-111 (`GET /v1/audio/voices` Danh sách Giọng TTS):** Trả danh sách giọng Muse TTS từ tệp tĩnh `packages/backend/data/voices.json` theo cấu trúc `{ object: "list", total, data: [{ id, name, gender, accent, tone, language, description, long_description }, ...] }`. Tự động lọc trước theo cấu hình `settings.voice_languages` nếu đang bật và khác rỗng (`BR-110`). Hỗ trợ lọc tùy chọn qua query params (lọc giao **AND** với cài đặt `voice_languages`): `gender`, `accent`, `tone` (khớp không phân biệt hoa thường), `language` (khớp theo tên nhóm chuẩn như `English (US)`, `English (UK)`, `Vietnamese`, `Japanese`, tên gom `"English"` cho tất cả 13 nhóm `English (*)`, hoặc mã gốc `eng`/`fra`, không phân biệt hoa thường) và `q` (tìm kiếm chuỗi con trên `id`, `name`, `accent`, `tone`, `description`, `long_description`).
- **FR-112 (`POST /v1/audio/speech` Sinh Giọng Nói TTS qua WSS):** Nhận JSON body chuẩn OpenAI mở rộng (`model` mặc định `"muse-tts"`, `input` bắt buộc, `voice` tùy chọn mặc định `"avocado_v2:MAI_01"`, `instructions` tùy chọn, `speed` tùy chọn, `response_format` mặc định `"mp3"` — hỗ trợ `"mp3"`, `"wav"`, `"url"`, `"json"`, `timeout` tùy chọn mặc định `180`s). Sau khi phân giải `voice`, kiểm tra ràng buộc `settings.voice_languages` (`BR-110`). Tiêm định dạng đích (`MP3` hoặc `WAV (16-bit PCM)`) vào prompt TTS gửi qua WSS pool, tải file audio từ `/media/raw/<path>` về `data/media/`, kiểm tra định dạng thực tế theo magic bytes / header WAV PCM16 và tự động fallback convert qua `ffmpeg` nếu Muse trả sai định dạng, đồng thời ghi nhận task `type="audio"` vào SQLite với đúng `media_filename` cuối cùng. Trả binary `audio/mpeg` khi `response_format="mp3"`, binary `audio/wav` (16-bit PCM) khi `response_format="wav"`, hoặc trả JSON `{ created, model, voice, voice_name, url, kind: "audio", bytes }` khi `response_format` là `"url"` hoặc `"json"`.

## 4. Quy tắc nghiệp vụ (`BR`)
- **BR-101:** Khi Global System Prompt đang bật trong `settings`, backend tự động chèn `<system>...</system>` vào đầu nội dung prompt gửi lên `muse.ai` (ngoại trừ yêu cầu TTS tại `POST /v1/audio/speech`, xem `BR-107`).
- **BR-102:** `POST /chat/subscribe` chỉ được gọi **sau khi** `POST /chat/stream` trả `200 OK` và xác nhận `session_id` tồn tại trên VM.
- **BR-103:** Khi xoay API key (`rotate`), key cũ mất hiệu lực ngay lập tức đối với các request mới tới `/v1/*`.
- **BR-104 (SSRF & Media Limits):** Mặc định từ chối URL mạng nội bộ (`MUSE2API_REF_IMAGE_PRIVATE_FETCH=0`) và đường dẫn file cục bộ (`MUSE2API_REF_IMAGE_LOCAL_FILES=0`). Giới hạn tối đa **10** media tham chiếu mỗi request, **40 MiB** mỗi item và **100 MiB** tổng dung lượng.
- **BR-105:** `MUSE2API_TOOL_PROTOCOL` mặc định tắt (`0`); khi tắt, không tiêm hướng dẫn JSON tool calling vào prompt.
- **BR-106 (Ánh xạ & Xác thực Giọng `voice`):** Tham số `voice` (nếu rỗng dùng mặc định `avocado_v2:MAI_01`) được phân giải theo thứ tự: (1) khớp chính xác `id` trong `voices.json`, (2) khớp không phân biệt hoa thường theo `name`, (3) khớp bảng OpenAI preset aliases (`alloy` → `avocado_v2:MAI_01`, `echo` → `avocado_v2:MAI_03`, `fable` → `avocado_v2:isabella`, `onyx` → `avocado_v2:magnus`, `nova` → `avocado_v2:paloma`, `shimmer` → `avocado_v2:lumi`). Nếu không khớp bất kỳ mục nào, trả `400 Bad Request` kèm gợi ý tra cứu `GET /v1/audio/voices`.
- **BR-107 (Thiết kế Prompt TTS & Emotion Cues):** Prompt gửi cho Muse tại `POST /v1/audio/speech` **không** tiêm Global System Prompt của chat để tránh nhiễu; chỉ rõ `voice_id` và `voice_name`, định dạng đích (`MP3` khi `response_format` là `"mp3"`/`"url"`/`"json"`, hoặc `WAV (16-bit PCM)` khi `response_format="wav"`), chèn `instructions` (nếu có) và `speed` (nếu có và khác `1.0`), yêu cầu đọc **nguyên văn** nội dung `input`, bảo toàn toàn bộ inline emotion cues (ví dụ `[laughs]`, `[sighs]`, `[whispers]`), không thêm lời dẫn/bình luận thừa. Khi nhận file về từ Muse với `response_format` là `"mp3"` hoặc `"wav"`, hệ thống xác thực header thực tế (MP3 frame/`ID3` hoặc RIFF/WAVE 16-bit PCM); nếu không khớp, tự động transcode fallback bằng `ffmpeg` (`pcm_s16le` cho `wav`, `libmp3lame` cho `mp3`) trước khi lưu kết quả cuối và trả cho client.
- **BR-108 (Ràng buộc Đầu vào & Định dạng TTS):** `input` sau khi trim phải có độ dài từ `1` đến `4096` ký tự (vi phạm trả `400`). `response_format` chỉ chấp nhận `mp3`, `wav`, `url`, `json` (không phân biệt hoa thường); mọi định dạng khác (`opus`, `aac`, `flac`, `pcm`, ...) trả `400 Bad Request`.
- **BR-109 (Lọc Danh mục Giọng Công khai):** Ẩn bản ghi nội bộ `avocado_v2:p1a1_short` (`Brand Founder`) khỏi `GET /v1/audio/voices` và khỏi danh sách giọng hợp lệ của `POST /v1/audio/speech`; loại bỏ các trường chấm điểm/ghi chú nội bộ (`aesthetics_mean`, `adherence_mean`, `aesthetics_mean_note`) khỏi payload API.
- **BR-110 (Áp dụng Cài đặt `voice_languages` cho cả Voices & Speech):** Khi `settings.voice_languages.enabled == true` và `settings.voice_languages.languages` không rỗng (xem [Settings Spec](../04_settings_and_cleanup/spec.md), `BR-303`):
  - `GET /v1/audio/voices` (và `/v1/voices`) chỉ trả về các giọng có nhóm ngôn ngữ nằm trong `settings.voice_languages.languages`; mọi query param từ client (`gender`, `accent`, `language`, `tone`, `q`) được lọc giao (**AND**) trong phạm vi tập giọng đó.
  - `POST /v1/audio/speech` kiểm tra nhóm ngôn ngữ của giọng sau khi phân giải `voice` (bao gồm cả trường hợp client bỏ trống `voice` và hệ thống phân giải về mặc định `avocado_v2:MAI_01` / `Aria`, hoặc dùng OpenAI alias `alloy`...): nếu giọng không thuộc danh sách ngôn ngữ đang bật thì **không fallback**, trả ngay `400 Bad Request` (`invalid_request_error`) nêu rõ ngôn ngữ của giọng chưa được bật trong cài đặt hệ thống và gợi ý tra cứu `GET /v1/audio/voices`.
  - Khi `enabled == false` hoặc `languages` rỗng (`[]`), không áp dụng giới hạn ngôn ngữ.
- **BR-111 (Định tuyến theo `supported_models` của Tài khoản & Fail-Fast `503`):**
  - Mỗi endpoint `/v1/*` cần chạy qua WSS pool được ánh xạ cố định vào 1 trong 4 loại model hỗ trợ của tài khoản (xem [Accounts Spec](../01_accounts_and_keepalive/spec.md), `FR-013`, `BR-005`):
    - `"chat"`: `POST /v1/chat/completions` (bao gồm cả trường hợp `messages` có `image_url`), `POST /v1/responses`.
    - `"image"`: `POST /v1/images/generations`, `POST /v1/images/edits`, `POST /v1/images/tasks`.
    - `"video"`: `POST /v1/videos`, `POST /v1/videos/generations`.
    - `"speech"`: `POST /v1/audio/speech`.
    - Các endpoint tĩnh (`GET /v1/models`, `GET /v1/audio/voices`, `GET /v1/voices`, `GET /v1/media/{filename}`) không chọn tài khoản nên không áp dụng bộ lọc này.
  - Pool chỉ đưa vào danh sách ứng viên (`_candidate_accounts(capability)`) các tài khoản có `capability` nằm trong `supported_models`, `enabled=true`, trạng thái không phải `expired` và chưa hết quota (`BR-004`).
  - **Fail-Fast `503 Service Unavailable`:** Khi không có tài khoản ứng viên nào cho `capability` tương ứng, hệ thống kiểm tra sớm trước khi mở SSE stream (với `stream=true`) và trước khi tạo task `queued` (với `POST /v1/videos*`, `POST /v1/images/tasks`, `async=true` trên `/v1/images/generations` & `/v1/images/edits`), trả ngay HTTP `503` theo chuẩn OpenAI error (`type: "service_unavailable_error"`) với thông điệp phân biệt rõ nguyên nhân:
    1. Không có tài khoản đang bật nào hỗ trợ loại model đó (vd: `"No enabled accounts support 'video'"`).
    2. Toàn bộ tài khoản đang bật hỗ trợ loại model đó đã hết quota (vd: `"All enabled accounts supporting 'video' have exhausted their quota"`).
    3. Không có tài khoản khỏe mạnh khả dụng cho loại model đó (vd: `"No healthy enabled accounts available for 'video'"`).

## 5. Tiêu chí nghiệm thu (`AC`)
- **AC-101:** Request `/v1/chat/completions` thiếu hoặc sai `Authorization` trả về `401 Unauthorized` chuẩn OpenAI.
- **AC-102:** `GET /admin/apikey` trả về đúng `raw_key` trong SQLite; sau khi bấm Rotate, key cũ bị từ chối và key mới hoạt động ngay.
- **AC-103:** Gọi `POST /v1/videos` (kèm hoặc không kèm ảnh tham chiếu) và `GET /v1/videos/{task_id}` trả về `progress` và URL `.mp4` hợp lệ phục vụ tại `/v1/media/{filename}`.
- **AC-104:** Gọi `POST /v1/responses` với `stream=true` và `instructions` trả về đúng chuỗi SSE `response.created` → `response.output_text.delta` → `response.completed`.
- **AC-105:** Truyền URL nội bộ (`http://127.0.0.1/...` hoặc `http://169.254.169.254/...`) làm ảnh tham chiếu bị chặn với `400 Bad Request` khi `MUSE2API_REF_IMAGE_PRIVATE_FETCH=0`.
- **AC-106:** Gọi `POST /v1/images/generations` với `"async": true` trả ngay `{id, status: "queued"}` và tra cứu được kết quả qua `GET /v1/images/tasks/{id}`.
- **AC-107:** Gọi `GET /v1/audio/voices` với Bearer key hợp lệ trả `200`, chứa danh sách giọng sạch không có `avocado_v2:p1a1_short`; lọc với `?gender=F&accent=British&q=soothing` trả đúng tập con khớp điều kiện.
- **AC-108:** Gọi `POST /v1/audio/speech` với `input` chứa inline emotion cues (vd `"[laughs] Hello there!"`) và `voice="Aria"` (hoặc `"avocado_v2:MAI_01"`, `"alloy"`), mặc định trả `200` với `Content-Type: audio/mpeg` là binary `.mp3` hợp lệ, đồng thời lưu file vào `data/media/` và ghi bản ghi `type="audio"` vào bảng `tasks`.
- **AC-109:** Gọi `POST /v1/audio/speech` với `"response_format": "wav"` trả `200` với `Content-Type: audio/wav` là binary `.wav` 16-bit PCM hợp lệ (tự động convert qua `ffmpeg` nếu Muse trả sai định dạng); gọi với `"response_format": "url"` trả JSON chứa URL `/v1/media/<filename>.mp3` truy cập được; gọi với `voice` không tồn tại, `input` rỗng / vượt 4096 ký tự, hoặc `response_format` ngoài `{mp3, wav, url, json}` (vd `"opus"`, `"flac"`) đều trả `400 Bad Request`.
- **AC-110:** Trang **API & Keys** hiển thị đầy đủ mục collapse Input/Output cho `GET /v1/audio/voices` và `POST /v1/audio/speech`; `GET /v1/models` có mặt các alias `muse-tts`, `tts-1`, `tts-1-hd`, `gpt-4o-mini-tts`.
- **AC-111:** Khi `settings.voice_languages` bật với `["English (US)", "Vietnamese", "Japanese"]`: `GET /v1/audio/voices` chỉ trả về `554` giọng thuộc 3 nhóm này (`541 + 7 + 6`); gọi `?language=English` trả đúng `541` giọng `English (US)` (tương thích ngược & lọc giao AND); gọi `?language=English (UK)` hoặc `?accent=British` hoặc `?language=French` trả `0` giọng; gọi `?language=Vietnamese` trả đúng `7` giọng.
- **AC-112:** Khi `settings.voice_languages` bật với `["English (UK)", "Vietnamese", "Japanese"]` (không có `English (US)`): gọi `POST /v1/audio/speech` với `voice="Aria"` (`English (US)`), `voice="alloy"`, hoặc **bỏ trống `voice`** đều trả `400 Bad Request` (không fallback sang giọng khác); gọi với giọng thuộc `English (UK)`, `Vietnamese` (vd `"Questioning Satchel"`) hoặc `Japanese` thành công bình thường.
- **AC-113:** Khi tài khoản A bật `["chat", "image", "speech"]` (tắt `"video"`) và tài khoản B bật `["video"]`: request `POST /v1/videos` chỉ chọn tài khoản B (không bao giờ chọn A); request `POST /v1/chat/completions` (kể cả có `image_url`), `POST /v1/responses`, `POST /v1/images/*` và `POST /v1/audio/speech` chỉ chọn tài khoản A (không chọn B).
- **AC-114:** Khi toàn bộ tài khoản đang bật đều tắt `"video"` (hoặc toàn bộ tài khoản bật `"video"` đã hết quota): gọi `POST /v1/videos` hoặc `POST /v1/videos/generations` trả ngay `503 Service Unavailable` với thông điệp rõ nguyên nhân và **không** tạo bản ghi task `queued`/`failed` trong bảng `tasks`; tương tự với `POST /v1/chat/completions` (`stream=true` và `stream=false`), `POST /v1/responses`, `POST /v1/images/*` (`async=true` và sync) và `POST /v1/audio/speech` khi thiếu tài khoản hỗ trợ loại tương ứng.
